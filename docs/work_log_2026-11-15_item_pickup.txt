1. 원본 계획

2. 구현 내용
- item.h에 bool HandleItemPickupRequest(int senderPlayerId, const ItemPickupData& request) 선언.
- item_pickup.cpp에 호스트 측 요청 검증 함수 작성. Visual Studio 프로젝트 및 필터 등록.
- 멀티 실제 게임의 실행 중 호스트에서만 검사. 싱글·렌더 테스트·게임 시작 전·클리어/게임오버 등은 거부.
- 연결에서 식별한 senderPlayerId(0~2)와 request.pickerId 일치 검사.
- approved=0 요청만 허용. 클라이언트가 보낸 확정 형태는 거부.
- 원격 플레이어의 소켓 슬롯이 INVALID_SOCKET이면 거부. 단순 connectedCount를 플레이어 ID로 간주하지 않음.
- 죽음·게임오버·변신 중인 플레이어 및 0 이하 충돌 크기 거부.
- 버섯/1UP/별/꽃/티노 5종을 실제 배열에 매핑하고 슬롯 0~29 검사.
- 아이템 활성 여부, 생성 모션 종료 여부, 유효한 충돌 크기 검사.
- 호스트 로컬 x+cameraX와 원격 플레이어의 월드 x를 구분해 아이템 월드 좌표와 충돌 검사.
- 기존 IsColliding과 같은 엄격한 겹침 판정: 경계만 닿으면 획득 불가.
- 좌표 합산 시 정수 오버플로 방지, 로컬 카메라 NaN/무한대 거부.

3. 이번 작업의 범위와 추가 결정
- 반환값 true는 현재 획득 조건을 통과했다는 의미이며 획득 확정이 아님.
- 검증 함수는 아이템 제거, 플레이어 효과, 전파, 승인 비트 변경을 수행하지 않음.
- 같은 요청을 반복 검증하면 계속 true일 수 있음. 중복 획득 방지 완료로 기록하지 않음.
- 변신 중 추가 획득 및 생성 모션 중 획득을 거부하는 것은 이번 B측 검증 기준. A/C에 전달할 확인 항목으로 남김.
- 싱글 기존 획득 경로는 수정하지 않았음. 멀티 획득 경로도 아직 이 함수에 연결되지 않았음.
- 검증 코드를 별도 파일로 분리한 것은 실제 아이템 상태를 사용하면서 독립 테스트가 가능하도록 한 추가 작업.
- 요청 종류/슬롯/권한/좌표 경계 검증과 독립 테스트는 원본의 플레이어·아이템 확인을 구체화한 작업.
